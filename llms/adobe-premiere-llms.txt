# Adobe Premiere Pro

> Adobe Premiere Pro is a professional non-linear video editor. Its programmable surface has two
> distinct halves. (1) The Premiere UXP API — an in-process JavaScript DOM (`require('premierepro')`)
> for plugins and panels that run inside the desktop application; there is no HTTP endpoint and no
> base URL. (2) The Adobe Creative Cloud Libraries REST API on `https://cc-libraries.adobe.io` — the
> HTTP surface a Premiere panel calls to read and write shared assets (colors, graphics, fonts,
> video). Anything an agent can call over the network lives in half 2.

Generated by API Evangelist on 2026-08-30 from Adobe's published documentation, the Adobe-published
OpenAPI at AdobeDocs/cc-libraries-api-spec, and the artifacts in this repository. This is a
third-party profile; Adobe publishes no llms.txt of its own (probed developer.adobe.com,
www.adobe.com and the Premiere UXP docs host on 2026-08-30 — all 404).

## Authentication

Every Creative Cloud Libraries call needs BOTH:
- `x-api-key` — the Client ID of an Adobe Developer Console project entitled to the API. Wrong key: 403.
- `authorization: Bearer <token>` — an Adobe IMS OAuth 2.0 access token. Wrong token: 401.

- [OAuth setup](https://developer.adobe.com/creative-cloud-libraries/docs/integrate/setup/oauth/): authorize `https://ims-na1.adobelogin.com/ims/authorize/v2`, token `https://ims-na1.adobelogin.com/ims/token/v3`, scopes `creative_sdk` `openid` `profile` `AdobeID`
- [Developer credentials](https://developer.adobe.com/creative-cloud-libraries/docs/integrate/setup/developer-credentials/): how to get the Client ID and Secret
- [Adobe Developer Console authentication guide](https://developer.adobe.com/developer-console/docs/guides/authentication/)

Two rules that break plugins if ignored, both from v26.3.0:
- `Sequence.setSelection` is now synchronous and returns a boolean, not a `Promise<boolean>`.
- `create*Action` calls must happen inside `project.lockedAccess(() => { ... })`.

## Creative Cloud Libraries REST API

Base URL: `https://cc-libraries.adobe.io` · version in path: `/api/v1/`

- [Documentation](https://developer.adobe.com/creative-cloud-libraries/docs/)
- [Endpoint reference](https://developer.adobe.com/creative-cloud-libraries/docs/api/)
- [Working with library elements](https://developer.adobe.com/creative-cloud-libraries/docs/integrate/guides/working-with-elements/)
- [OpenAPI (Adobe-published, Swagger 2.0)](https://raw.githubusercontent.com/AdobeDocs/cc-libraries-api-spec/main/openapi.json) — 25 operations across libraries, elements, representations, bookmarks, public libraries and search

Conventions:
- Pagination: `start` (0-based, required with `limit`), `limit` (max 10 on libraries), `orderBy` (default `-modified_date`, `-` reverses, commas combine). Not available on public libraries.
- Concurrency: `if-match` / `if-none-match`; a failed precondition returns 412.
- Tracing: send `x-request-id`; it returns as `xactionid` on the resulting event.
- Idempotency: **not supported**. There is no `Idempotency-Key` header; a repeated POST creates a duplicate.
- Errors: `application/json` with an `ErrorResponse` body. Not RFC 9457.
- Rate limits: 429 is declared, but Adobe publishes no numeric limit and no `Retry-After` or `RateLimit-*` headers. Back off blind.

Reversibility — read this before deleting anything:
- `DELETE /api/v1/libraries/{libraryId}/elements/{elementId}` **archives** the element. Reversible.
- `POST /api/v1/libraries/{libraryId}/archive` restores archived elements.
- `DELETE /api/v1/libraries/{libraryId}/archive[/{elementId}]` is a **permanent** purge.
- Adobe states no archive retention window, so the reversal is available but untimed.

## Events and webhooks

- [Configuring webhooks for Creative Cloud Libraries events](https://developer.adobe.com/creative-cloud-libraries/docs/integrate/guides/configuring-events-webhooks/)
- [Event properties](https://developer.adobe.com/creative-cloud-libraries/docs/integrate/references/event-properties/)
- [Sample event payload](https://github.com/AdobeDocs/cc-libraries-api-samples/blob/main/sample-events/cc-library-created.json)

Delivered through Adobe I/O Events as CloudEvents. Three types: Library Created, Library Deleted,
Library Updated. There is no element-level subscription — an Updated event means "something in this
library changed"; re-read the element list to find out what. Adobe challenges the webhook URL before
activating the registration. No AsyncAPI document is published.

## First-party packages

- [`@adobe/premierepro`](https://www.npmjs.com/package/@adobe/premierepro) 26.3.0 (2026-06-12) — TypeScript declarations for the Premiere UXP API. Apache-2.0.
- [`@adobe/eslint-plugin-premierepro`](https://www.npmjs.com/package/@adobe/eslint-plugin-premierepro) 26.3.0 (2026-06-12) — lint rules that catch `lockedAccess` and Action misuse. Apache-2.0.
- [`@adobe/cc-ext-uxp-types`](https://www.npmjs.com/package/@adobe/cc-ext-uxp-types) 7.3.1 (2023-10-19) — shared UXP platform types.

There is no first-party client library for the Creative Cloud Libraries REST API and no first-party
MCP server for Premiere Pro. The Premiere MCP servers on npm are community projects, all local-stdio.
